# 후속 질문·증상 분류·반복 전사·스크롤 수정

## 후속 질문

LLM의 설명용 `context`를 질문 앞에 붙이던 처리를 제거했다. `context`가 비어 있어도 정상 질문을 수용한다. LLM에 의문문만 작성하도록 지시하고, 예전 형식의 설명문이 `question` 안에 들어오면 의문문만 남긴다. 소수 수치가 문장 분리 과정에서 바뀌지 않는지도 검사한다. 유효한 질문이 없으면 근거 원문 질문을 유지한다.

화면에서는 추천 이유 설명을 생략한다. API의 `reason`, 확인 목적과 우선순위, 근거 원문과 문서·페이지 정보는 유지한다. 요약과 긴급도 처리에는 변경이 없다.

## 알려주신 파일의 전신쇠약 누락

대상은 `651e464d69a4f266f06268a0_20220101.wav` 전체 100.8초다. 전사·분류를 로컬에서 실행했으며 통화 내용을 LLM API로 보내지 않았다.

| 입력/설정 | 전신쇠약 점수 | 기준 0.5 이상 검출 |
| --- | ---: | --- |
| 정답 전사 | 0.6228 | 예 |
| 변경 전 파일 인식, small beam 5 | 0.3442 | 아니요 |
| 복원한 파일 인식, small beam 1 | 0.5918 | 예 |

이전에 사용하던 파일 beam 1을 기본 설정·`.env`·예시 설정에 복원했다. 체크포인트, 토크나이저, 학습 때의 512-token/stride 128 입력, 8개 독립 sigmoid와 표시 기준 0.5는 유지했다. 실제 파일을 새 설정으로 다시 읽어 `STT → KoELECTRA` 검출을 확인했다. 결과는 [symptom_audio_regression.json](symptom_audio_regression.json), 다른 설정 비교는 [followup_regression_notes.json](followup_regression_notes.json)이다.

이는 해당 증상의 검출 복구이며 전체 전사의 정확도 개선을 의미하지 않는다. 같은 파일의 문자 오류율은 beam 5에서 30.79%, beam 1에서 33.65%였다. 더 큰 turbo는 18.62%였지만 모델 로딩을 포함해 약 123초가 걸렸으므로 이번 기본 설정에 적용하지 않았다. 다른 파일에서도 같은 증상 점수나 정확도를 보장하지 않는다.

```powershell
.venv/Scripts/python.exe -m tools.verify_symptom_audio `
  --audio "C:/Users/lemon/Desktop/Sample/01.원천데이터/서울/구급/651e464d69a4f266f06268a0_20220101.wav" `
  --expected-code general_weakness --output tmp/symptom-check.json
```

이 검증 도구는 전사 원문을 출력하거나 저장하지 않고 검출 결과와 수치만 출력한다. 로컬 모델과 토크나이저가 필요하다.

## 비정상적인 긴 반복

Whisper 생성 단계에 반복 n-gram 제한과 입력 길이에 따른 토큰 상한을 적용했다. 출력에 동일 단어 12회 이상 또는 동일 글자 20회 이상의 비정상 반복이 남으면 같은 음성을 한 번 재인식한다. 경계 복구와 재인식이 중첩되더라도 추가 반복 재인식 예산은 입력당 한 번이다.

재인식 후에도 같은 긴 반복이 남으면 그 반복 부분만 제외하고 앞뒤의 다른 발화는 보존한다. `transcript.warnings`와 응답 `warnings`에 원음 확인 안내를 넣고 이후 실시간 업데이트에서도 유지한다. 짧은 실제 반복 응답과 의료 용어를 삭제하는 사전은 사용하지 않는다. 반복 감지·재인식 성공/실패·일반 반복 보존을 회귀 검사했다. 실제 신고자의 장시간 말더듬과 모델 반복을 완벽히 구별하는 기능은 아니므로 경고 구간은 원음 확인이 필요하다.

## 전사 카드 스크롤

카드 내부의 현재 위치가 맨 아래에서 4px 이내일 때만 새 전사를 따라간다. 사용자가 위로 스크롤하면 위치를 유지하고, 다시 맨 아래로 내리면 자동 추적을 재개한다. 새 전사 컨테이너가 만들어질 때 추적 상태를 초기화한다.

실제 브라우저에서 합성 발화를 추가하며 확인했다. 30→31개 발화에서 맨 아래 간격 1px 유지, 위쪽을 읽으며 31→32개 발화 추가 시 scrollTop 2194px 유지, 맨 아래 복귀 후 32→33개 추가 시 간격 1px을 확인했다. 검증용 페이지·서버는 정리했다.

# 개인정보·실시간 음성 안정화 — 2026-11-06

사용자 결정: **요약·긴급도 AI를 보류하고 음성·증상·매뉴얼 질문부터 안정화**한다.

향후 외부 LLM이 필요하면 공개가 확인된 매뉴얼만 넣어 질문 후보를 사전에 만들고 검수한 뒤 서버에 등록한다. 실제 통화 중에는 서버가 상담 내용에 맞는 후보를 로컬에서 선택한다. 요약이 필요해지면 서버에서 확인된 항목을 템플릿에 채울 수 있다. 이름과 전화번호를 가려도 나머지 문맥에 구체적인 장소나 병력이 남을 수 있으므로 실제 신고와 관련된 텍스트는 외부 모델에 보낼 입력에서 제외한다.

## 현재 처리와 개인정보 경계

브라우저의 음성/대화 → 내부 FastAPI → 로컬 Whisper·화자 모델 → KoELECTRA → 로컬 매뉴얼 상태·분기·Chroma 검색이다. `.env`와 예시의 `RAG_LLM_PROVIDER=disabled`, `LLM_PRIVACY_MODE=local_only`, `LLM_CLOUD_POLICY_ACKNOWLEDGED=false`를 적용했다. 현재 경로는 외부 LLM 요청을 하지 않는다. 요약·긴급도 AI 카드와 다운로드 항목을 숨기며 로컬 규칙으로 긴급도 단계를 대신 지정하지 않는다. 과거 5단계와 원문의 분류는 별개다.

`app/privacy.py`는 RAG와 레거시 Gemini 양쪽의 외부 호출 전에 정책을 검사한다. 향후 로컬 호환 LLM은 숫자 loopback 주소만 허용한다. 외부 사용은 `redacted_cloud`와 정책 확인을 모두 명시해야 하며 HTTPS·식별정보 가림을 적용한다. **가림은 완전한 익명화가 아니므로 현재 사용자 결정에 따라 외부 사용을 활성화하지 않았다.** 현재 PC의 소형 로컬 LLM은 가상 대화 품질 검사에서 부적합해 채택하지 않았고 시험 서버·모델을 제거했다.

앱은 분석 기록·대화·결과 DB를 만들지 않는다. Chroma에는 첨부 매뉴얼만 저장한다. 원음 재검토를 위해 녹음 한도 안의 PCM을 세션 메모리에 유지하고 종료 시 참조를 해제한다. 600초 PCM은 약 19.2 MB이며 큐·디코딩 복사본은 별도다. 마이크/PC 원음 미리 듣기도 브라우저 메모리의 Blob을 사용한다. 업로드는 multipart 파서의 OS 임시 파일을 거칠 수 있고 요청 종료 시 닫힌다. 클라이언트의 명시적 다운로드는 로컬 파일을 만든다. 임베딩 쿼리의 대화 캐시를 제거했고 LangSmith 추적·Chroma 텔레메트리는 비활성화했다. 이 조치는 서버 접근권한, 전송 암호화, 운영 로그, OS 메모리/임시 파일 정책을 포함한 기관 보안 검증을 대신하지 않는다.

## 음성 입력과 원음 복구

- **파일 직접 입력**: 선택한 파일을 브라우저에서 디코딩해 실제 재생 속도의 PCM으로 전송한다. 스피커→마이크 재녹음이 필요 없다.
- **PC·통화 오디오**: 사용자가 공유한 대상의 오디오만 전송한다. 브라우저가 화면 권한도 요구할 수 있으나 영상은 전송하지 않는다. 마이크는 혼합하지 않으므로 양쪽 발화가 포함된 공유 음원인지 확인해야 한다.
- **마이크**: 현장 대화 입력을 유지한다. 녹음 후 원음을 다시 들어 실제 수음 문제와 인식 오류를 구분할 수 있다.
- **CPU 적체**: 큐에 대기 중인 연속 PCM을 최대 3개/설정 18초까지 묶어 반복 호출 부담을 줄인다. PCM을 버리거나 속도를 바꾸지 않는다. 이전 음성 문맥 6초는 유지한다.
- **연속 짧은 응답**: 4개 이상이 2초 이상 이어지면 실제 응답일 수도 있으므로 삭제하거나 증상을 추측하지 않고 `needs_review`로 표시한다. 확인 전에는 증상 분류·매뉴얼 상태의 근거에서 제외한다.
- **종료 시 재검토**: 가장 긴 의심 구간 한 곳에 대해 문맥을 포함한 최대 30초 원음만 로컬 재인식한다. 이 PC에서는 보관 중인 `models/whisper-turbo`를 사용한다. 모델이 없는 환경은 `WHISPER_REPAIR_MODEL`을 비워 기존 모델을 재사용한다. 새 결과와 겹치지 않는 기존 발화는 보존하고 미해결 발화는 표시한다. LLM으로 누락 내용을 만들어 채우지 않는다.
- **정정 전파**: `transcript.revision`을 올리고 증상·질문을 다시 계산한다. 화면은 이전 revision에 대한 늦은 분석 결과가 정정 내용을 덮지 못하게 한다. 하단 추적/위쪽 대화 읽기 동작은 유지한다.

## 원본 음성과 통제된 복구 시험

대상은 사용자가 지정한 `651e464d69a4f266f06268a0_20220101.wav`이다. 음성·정답 전사는 외부 API로 전송하지 않았고 보고서에는 집계값만 저장했다.

1. 원본 디지털 PCM 100.8초를 현재 small 6초+문맥 6초 방식으로 처리했을 때 STT 63.844초, CER 27.68%였다. 문제로 제시된 48~72초의 연속 “네”는 재현되지 않았다. 입력 경로의 영향은 의심되지만 확정된 원인으로 주장하지 않는다. 문맥을 없앤 비교는 CER 34.61%였으므로 문맥을 유지한다. `stt_reply_ablation.json` 참조.
2. 별도 **통제 시험**에서는 48~66초를 의도적으로 “네”로 바꾸고 production 원음 검토 경로를 실행했다. 정답 라벨은 손상하지 않은 주변 구간 구성에만 사용했고 손상 구간을 복원하는 입력으로 사용하지 않았다. 원음 검토에서 발화 11개/169자를 복구했고 복구된 발화만 KoELECTRA에 넣어 전신쇠약 0.8108을 얻었다. 기준은 기존대로 각 증상 독립 sigmoid **0.5 이상**이다.
3. 이 재검토는 CPU에서 50.302초 걸렸고 미해결 구간 2개가 남았다. 시간 경계가 정답 발화 중간을 가를 수 있어 참고 CER 29.32%는 전체 통화 성능 지표가 아니다. 모든 지연·오인식을 해결했다는 결과도 아니다. `audio_review_regression.json` 참조.

재현:

```powershell
.\.venv\Scripts\python.exe -m tools.verify_audio_review --audio <원음.wav> --labels <정답.json> --output tmp/review-metrics.json
```

검토 시간이 부담스러우면 `REALTIME_REVIEW_ENABLED=false`로 자동 재검토만 끌 수 있다. 이때 불확실 구간 표시는 유지된다. 고성능 GPU/기관 내부 STT 도입은 같은 원음·정답으로 오류율과 전체 지연을 평가한 후 결정해야 한다.

## 단순 질문 개선

질문은 외부 LLM에 대화를 넣지 않고 **로컬 확인 상태 + 주증상 프로토콜 + 원문 조건**으로 선택한다. 기본 의식·정상 호흡이 미확인일 때는 이를 생략하지 않는다. 팔 마비 보고에는 KoELECTRA의 8개 범주와 별도로 검색 가설 P02를 활성화해, 원문의 발음·얼굴/사지 마비·감각 질문을 이용한다. 원문 3~5번 중 “예” 조건이 확인됐을 때만 발생 시각 질문을 활성화하고 이미 확인된 시각은 재질문하지 않는다. 실제 원문 질문 번호를 조회해 조건을 해석하며 추출 순서로 번호를 추정하지 않는다.

예: “환자분이 말을 하지 못하거나, 발음이 정확하지 않은 상태인가요?”, “환자분의 팔·다리가 저리거나 감각이 이상한 곳이 있나요?”, 조건 충족 시 “말씀하신 증상은 언제 처음 생겼나요?”

`question_bank.py`는 개발자가 작성한 일정·문구 규칙이고 `source_excerpt`는 보존된 PDF 원문이다. 새 의료 기준·행동 검사·치료 지시를 추가하지 않았다. 화면은 질문만, 근거는 문서명·페이지의 일반 텍스트로 표시한다. 내부 질문 ID는 유지하되 화면에 노출하지 않는다. 자연어 인식 범위에는 한계가 있으며 전문가 검증 전 연구용이다.

## Notion과 외부 AI에 대한 참고

[Notion 공식 설명](https://www.notion.com/help/ai-meeting-notes)은 전사와 AI 요약을 제공하고 데스크톱 앱이 시스템 오디오와 마이크를 함께 캡처한다고 설명한다. 확인한 자료에서 정확한 STT 모델과 전사 교정 알고리즘은 공개하지 않았다. LLM으로 모든 전사 오류를 복구한다고 단정할 수 없다.

# 실시간 전사 품질 회귀 검증 (2026-11-05)

2026-11-16 실시간 재생 비교에서는 현재 PC의 `TORCH_CPU_THREADS`를 2에서 1로 조정하고, 발화 전사를 화자·매뉴얼 결과보다 먼저 보내도록 했다. 새 PCM이 전사보다 한 구간 이상 앞서면 매뉴얼 질문은 구조 검색으로 제공하고 로컬 의미 검색은 음성 처리가 따라잡은 뒤에 실행한다. 녹음 종료까지 새 발화가 없으면 마지막 발화 기준으로 의미 검색을 완료한다.

같은 한국어 통화 36초를 100ms 단위로 재생한 서버 측 시험에서 시작부터 마지막 전사까지 55.3초에서 42.7초로 줄었다. 첫 전사는 12.2초에서 11.4초로 줄었고 두 결과의 문자 오류율은 같았다. Whisper small, 6초 입력, 6초 문맥, beam 2로 비교했다. 3초 쉼 분할과 4.5초 고정 구간은 비교 표본에서 오류가 늘었다. 이 수치는 단일 구간의 서버 시험이며 실사용 지연은 CPU 부하와 통화에 따라 달라진다.

2026-11-06 추가 안정화(직접 음성 입력, 의심 응답·원음 재검토, 최신 시험과 한계)는 [개인정보·음성 안정화 기록](PRIVACY_STABILITY.md)에 있다.

아래 표는 실시간 분할 방식 변경 시점의 비교 기록이다. 이후 파일 beam 1 복원·반복 생성 방지와 실제 파일의 증상 검출 확인은 [후속 수정 기록](FOLLOWUP_FIXES.md)에 별도로 기록했다.

증상 단어가 반복되는 문제를 해결한 뒤에도 짧은 음성 조각에서 문맥을 잃는 문제가 남아 있었다. 기존 속도 튜닝이 새 음성을 최대 4초, 쉼이 있으면 1.5초부터 분할하고 그때 이전 음성 문맥을 비우도록 바뀐 것이 원인 중 하나였다. 텍스트 힌트를 다시 넣거나 LLM으로 전사 내용을 추측해 바꾸지는 않았다.

## 적용한 변경

- 새 음성은 최대 6초씩 처리한다. 이전 음성 최대 6초를 다음 인식 입력에 보존한다.
- `REALTIME_PAUSE_SPLIT=false`가 기본이다. 선택적으로 쉼 분할을 켜더라도 음성 문맥을 지우지 않는다.
- 경계의 겹친 음성은 단어 타임스탬프로 제외한다. 경계에 걸친 단어와 실제 반복 응답을 보존한다.
- 파일 디코딩은 기본 VAD와 저신뢰 디코딩의 temperature 재시도를 복원했다. 실시간은 CPU 지연을 제한하기 위해 한 번의 디코딩을 유지한다.
- `hotwords`, `initial_prompt`, `prefix`는 파일·실시간·경계 재처리에서 모두 사용하지 않는다.
- 로컬 `.env`, 예시 설정, 공개 API 예시, 프런트엔드의 기본 표시 주기를 맞췄다.

## 로컬 통화 비교

같은 통화를 같은 16 kHz 모노 PCM으로 변환한 뒤 100 ms 프레임으로 나누어 비교했다. 표의 오류율은 띄어쓰기·문장부호를 제외한 문자 오류율(CER)이며 낮을수록 좋다. 숫자 발음과 숫자 표기는 별도로 통일하지 않았다.

| 통화 앞부분 | 길이 | 변경 전 CER | 변경 후 CER | 변경 전 STT 시간 | 변경 후 STT 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 지하철 통화 | 40.270초 | 40.78% | 27.18% | 30.5초 | 23.7초 |
| 비교 통화 A | 38.684초 | 66.22% | 35.81% | 36.0초 | 20.0초 |
| 비교 통화 B | 41.791초 | 69.61% | 51.93% | 32.0초 | 19.3초 |
| 합계/문자 수 가중 | 120.745초 | 57.57% | 37.94% | 98.5초 | 63.0초 |

환경은 `small`, CPU int8, 4 threads, 실시간 beam 2이며 두 설정 모두 텍스트 힌트는 꺼져 있다. 6초와 8초 창을 같은 세 표본에서 비교해 6초를 기본으로 선택했다. 독립된 평가 세트는 아니다. 상세 수치와 설정은 [stt_streaming_regression.json](stt_streaming_regression.json)에 보관했다. 통화 음성·전사·라벨 원문은 보고서에 넣거나 외부 API로 전송하지 않았다.

Whisper turbo도 프로젝트의 `models/whisper-turbo`에 내려받아 비교했다. 지하철 표본에서 CER은 16~19%였지만 실시간 처리에 58~70초가 걸려 40초 입력보다 느렸다. 현재 CPU의 실시간 기본 모델은 `small`로 유지했다. 내려받은 비교용 모델은 Git에서 제외한다.

## 재현

라벨 JSON은 `utterances: [{text, startAt, endAt}]` 형식이며 시각은 밀리초다. 표본 끝은 가능한 한 완결된 발화의 `endAt`에 맞춘다. 벤치마크는 전사 대신 수치만 출력한다.

```powershell
.venv/Scripts/python.exe -m tools.benchmark_stt_streaming `
  --audio "통화.wav" --labels "통화.json" --seconds 40.27 `
  --variants "pauses4:2:2,fixed6:2:6" --output tmp/stt-comparison.json
```

변형 이름은 `분할방식과초:beam:문맥초`다. `pauses4:2:2`는 이전 설정의 조기 분할·문맥 초기화를 시뮬레이션하고 `fixed6:2:6`은 현재 기본값을 시뮬레이션한다. 큰 모델을 재비교할 때는 `--model models/whisper-turbo`를 추가한다. `--legacy-decoder`는 이전 라이브러리 기본 재시도/VAD 설정을 비교하는 실험 옵션이다.

일부 구간의 오인식은 여전히 상당하다. 위 결과는 세 통화의 일부 구간에 대한 설정 비교이며 일반화된 인식 정확도나 의료적 정확성의 검증이 아니다. 처리 시간은 모델 로딩, 화자 모델, 증상 분류, LLM을 제외한 한 번의 로컬 STT 실행 결과다. 실제 마이크·브라우저의 잡음 제거와 스피커 재녹음은 검증 범위에 포함하지 않았다. 설정 반영에는 백엔드 재시작과 새 녹음이 필요하다.
